How we started

The user need that started everything

A single user story drove the feature from day one.

I want to create a new BPMN model that fulfils these requirements so that I can publish it in my workspace:

  • 1

    Conforms BPMN 2.0 syntax

  • 2

    Accurately represents as-is or to-be processes presented in various formats and sources — SPOC, wiki, image, table, report, meeting transcript, process analysis

  • 3

    Compliant: meets the Signavio workspace standards set for BPMN modeling

  • 4

    Standardized with the existing processes and dictionary

01
User problem

The first model is still too much work

Teams that already know the process shouldn't have to start from scratch.

Our users deal with stakeholders who often know the process, but their inputs arrive as notes, screenshots, tables, or documents — not clean BPMN. Process knowledge is scattered across tools and in different formats. The feature should remove the blank-canvas step and get them to a model they can review, correct, and share without need for BPMN expertise.

Blank-canvas tax

Teams spend time translating before they can discuss and improve the actual process.

Expertise barrier

Business users need an easier first step without becoming BPMN experts.

Uncompliant repository

Compliance and standardization relies on the modeler's expertise or choice.

02
Outcomes

The feature is successful when customers reach a trusted, editable BPMN model faster

Users

Create a first BPMN draft from the material they already have, then review and modify without BPMN expertise instead of starting from blank. BPMN compliance, dictionary linking, and documentation attributes make the model useful in real workspaces.

Business

Democratize modeling so more business users can contribute to standard process work.

Trust

Need for trust is observed to be higher with AI products. Privacy, personal-data guidance, cross-border transfer, and verification need to be visible in the experience.

03
Use learnings to decide

What we've learned so far

The next iteration should respond to how teams actually try the feature.

01

Modeling a new process starts with blank canvas, best practice, or an existing model as reference

Modifying or duplicating old diagrams and best practices requires expert knowledge, which hinders the democratization of modeling.

02

Our differentiator is workspace context, best practices, and governance

Standardization and compliance is the most time-consuming part after draft generation.

03

Adoption of AI needs a safe first step when activation is cumbersome

Labs access and feedback sessions let customers try the capability while we learn.

04

AI should ask for clarification instead of silently filling gaps

Most companies have built their own AI preparation layer before our tool.

For some mature users, creating new diagrams is no longer the primary use case.

04
Where we are going

Two user goals shaping the roadmap

As-is

I want to create and maintain compliant and standardized as-is processes that accurately represent my process reality.

To-be

I want to model compliant and standardized to-be processes that reflect on best practices, transformation initiatives, process analysis, and business rules.

Current product bets

Focus the roadmap on making the first model useful, standard, and editable.

AI-assisted modeling on the go

A chat-based AI assistant interacts with the canvas directly in NGM, enabling other teams to build AI skills as well.

Improve accuracy continuously

Improve LLM, architecture, and system prompt.

Modeling assistant is accessible in the engagement layer — PCA, MCP, Joule.

Context-aware process generation and modifications based on repository, dictionary, and modeling conventions.

Generate context-aware process improvement recommendations based on SAP best practices, suite repository, and atoms — PCA analysis on top — and reflect on to-be processes.
